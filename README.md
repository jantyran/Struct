# Struct

Struct は、`MKTキャンペーン運用デスク` として使う認証付きのキャンペーン管理アプリです。  
キャンペーンやイベントごとの進行管理、構造化された情報管理、生成コンテンツ管理、AI 生成を 1 つの画面群で扱います。

## 主な機能

- プロジェクト管理
  - ユーザー定義の `プロジェクト種別` ごとに案件を管理
  - 種別ごとにフェーズ、フィールド、生成コンテンツを設定
  - セクションごとに UI 配置を管理し、項目をドラッグ&ドロップで配置
  - フェーズはプロジェクト詳細上部のパス UI で管理
- Global Assets
  - 任意のオブジェクトを作成
  - オブジェクトごとに項目定義とレコードを管理
  - 項目は `参照` / `複数参照` で他オブジェクトを参照可能
- プロジェクト情報の構造化
  - 標準項目に加えて、設定由来の `フィールド` を案件ごとに入力
  - 項目設定ではラベル、キー、型、参照先、選択肢などの項目情報のみを管理
  - `1列` / `2列` レイアウトや表示セクションは `セクション設定` 側で管理
  - `グループ` / `繰り返しグループ` でまとまりのある入力にも対応
  - `参照` / `複数参照` で Global Assets のレコードを参照可能
- 生成コンテンツ管理
  - `生成コンテンツ設定` で出力テンプレートを定義
  - チャネル、テキスト形式、トーン、必須要素、構成例、指示を管理
  - 各プロジェクト種別には使う生成コンテンツだけを複数紐づけ
- AI 生成
  - AI プロバイダを設定画面から切り替え
  - `Gemini` / `OpenAI` / `Anthropic` に対応
  - API キー、モデル、Base URL は組織レベル設定として保持
  - プロジェクト詳細から追加指示付きで生成可能
- 共同作業
  - オーナーによる招待 URL 発行
  - 招待受諾による共同編集

## 現在の画面構成

- `/`
  - ダッシュボード
- `/global-assets`
  - オブジェクト一覧と管理
- `/global-assets/[objectId]`
  - オブジェクト設定、項目設定、レコード管理
- `/project-types`
  - プロジェクト設定
  - 項目定義と UI 配置定義を分離
  - セクション単位のドラッグ&ドロップ配置
- `/projects/[id]`
  - プロジェクト詳細、フェーズ管理、フィールド入力、生成コンテンツ生成・編集
- `/settings`
  - 設定ハブ
- `/settings/ai`
  - AI 設定
- `/settings/content-templates`
  - 生成コンテンツ設定
- `/about`, `/guide`
  - 公開向け説明ページ

## セットアップ

### 推奨環境

- Node.js v23 以上

### 手順

```bash
cp .env.example .env
npm install
npm run dev
```

`.env` では以下を設定してください。

```env
JWT_SECRET=任意の長い文字列
NEXT_PUBLIC_BASE_URL=http://133.18.123.87:38427
NEXT_PUBLIC_BASE_PATH=
```

補足:

- ルート配備が既定です
- サブパス配備時のみ `NEXT_PUBLIC_BASE_PATH=/struct` のように設定してください
- AI API キーは `.env` ではなく、ログイン後の `設定 > AI設定` から保存する運用です

## 起動ポリシー

- 開発確認用: `npm run dev`
- ポート: `0.0.0.0:3002`
- 用途: コード変更をビルドなしで即時反映して確認する

- 本番確認用: `npm run build && npm run start`
- ポート: `0.0.0.0:38427`
- 用途: ビルド済みの安定版を確認する

補足:

- `npm run start` は 38427 の本番起動です
- `npm run start:dev` は `npm run dev` と同じく 3002 の開発起動です
- 招待URLなど外部共有前提のURL生成には `NEXT_PUBLIC_BASE_URL` を使うため、通常は 38427 側のURLを設定したままで問題ありません

## 今後の実装予定

### プロジェクト内日常運用

- プロジェクトごとの `ToDo`
- プロジェクトごとの `ノート`

どちらも案件に紐づく日常運用情報として扱い、進行管理とメモ蓄積をプロジェクト画面内で完結できるようにする予定です。`ToDo` は日々の実務タスク管理、`ノート` は打ち合わせ記録や判断メモの蓄積を目的とします。

### AI セットアップアシスタント

ユーザーやシステム管理者の代わりに、AI が対話形式でプロジェクトの設定・オブジェクト設計を自律的に構築する機能です。  
「何を管理したいか」を自然言語で伝えるだけで、必要な構造を AI が提案・生成します。

#### 対象スコープ

| 機能 | 概要 |
| :--- | :--- |
| **プロジェクト種別の自動生成** | 業務目的をヒアリングし、フェーズ・フィールド・セクション・生成コンテンツ設定を一括構築 |
| **Global Assets オブジェクト設計** | 管理したいエンティティを説明すると、項目定義・型・参照関係を提案して作成 |
| **既存設定のリファクタリング提案** | 既存のプロジェクト種別を分析し、重複・過不足・構造上の問題点を指摘・修正 |
| **テンプレートからの展開** | 「SNS広告運用」「展示会出展管理」等のユースケーステンプレートを AI が解釈してカスタマイズ生成 |

#### 操作フロー（想定）

1. **対話フェーズ** — AI がユーザーへ業務概要・管理対象・フェーズ数などをチャット形式で質問
2. **設計プレビュー** — AI が生成する設定内容を JSON プレビューとして画面に表示
3. **確認・修正** — ユーザーが修正指示を自然言語で追加入力し、再生成
4. **一括適用** — 確定後、プロジェクト種別・オブジェクト・フィールド・セクションをトランザクションで一括保存

#### 技術方針

- AI への指示には、既存の組織レベル AI 設定（Gemini / OpenAI / Anthropic）を流用
- Struct の内部スキーマ（フィールド型定義・セクション構造）を System Prompt として注入し、有効な JSON を生成させる
- 生成結果は既存の API エンドポイント（`/api/project-types`, `/api/objects` 等）へそのまま投入できる形式に正規化
- 設定の「Undo」に対応するため、適用前のスナップショットを DB に保存するロールバック機構を用意

## 現在整理中の設計方針

- `項目設定`
  - 項目そのものの情報だけを管理する
  - 対象はラベル、キー、型、選択肢、参照先、子項目など
- `セクション設定`
  - UI 上の見せ方を管理する
  - 対象はセクション順、項目の所属先、セクション内順序、`1列` / `2列`
  - Salesforce 風に、未配置項目ボックスと各セクション間でドラッグ&ドロップ配置できる形を目指す
  - 未配置の項目と、すでにどこかへ配置済みの項目は色分けで判別できるようにする
